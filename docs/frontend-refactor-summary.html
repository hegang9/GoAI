1重构背景与问题诊断

原前端存在三个结构性问题，导致后续 UI 微调成本高、改动容易在多个文件间漂移：

1.1 AIChat.vue 是 1100+ 行的巨型组件

单文件混合了 6 类本不相关的职责：

  • 会话管理（加载 / 切换 / 创建 / 同步历史）
  • 消息发送（普通 + 流式）
  • SSE 协议解析（fetch + ReadableStream + 行分割 + [DONE] / JSON 分支）
  • 百度 TTS 任务创建 + 30 次轮询播放
  • RAG 文档列表拉取 + 文件上传
  • Markdown 渲染、自动滚动、模型 / 流式 / 检索范围切换

1.2 跨页面样式大面积重复 复制粘贴

  • AIChat.vue 与 ImageRecognition.vue：.session-list / .top-bar / .chat-messages / .message / .user-message / .ai-message / .chat-input / @keyframes float / messageSlideIn —— 几乎一字不差
  • Login.vue 与 Register.vue：.login-container / .register-container、.login-card / .register-card、@keyframes float/slideIn/glow/fadeIn —— 完全重复
  • 4 个页面都用同一段 linear-gradient(135deg, #667eea 0%, #764ba2 100%) + SVG 颗粒背景

1.3 缺少层级 平铺

没有 layouts/、没有 composables/、没有 components/，所有视图都是"平铺 + 自包含"。改一个气泡样式要同时改两个文件、改渐变色要改四个文件。

2重构目标与策略

核心原则：功能、接口契约、路由全部不变；只重构"组件关系"，让 UI 微调的着力点集中、可单点修改。

采用三层拆分策略，对应三种不同的"变化频率"：

层级职责变化频率目录
视图层页面级编排：装配哪些子组件、串起哪些 composable低views/
组件层纯展示 + props/events，UI 微调的最小着力点中components/
行为层可复用副作用逻辑（网络 / SSE / 轮询 / 定时器）低composables/
布局层跨页面共享的骨架极低layouts/
视觉层设计 token + 共享样式中assets/styles/

4组件关系图

views (编排层)
  ├─ AIChat ────┬─ ChatLayout (外壳)
  │             ├─ SessionSidebar / ChatTopBar / MessageList / ChatInput (子组件)
  │             └─ useChatSession + useChatSend + useRagFiles + useTTS (composables)
  │
  ├─ ImageRecognition ── 复用 ChatLayout + MessageList + MessageBubble
  ├─ Login / Register ── GradientBackground + AuthCard
  └─ Menu ── GradientBackground + 数据驱动菜单项

依赖方向（单向，无循环）：
  views ─→ layouts + components + composables ─→ utils/api
  components  ←  只接收 props / 抛 events，零业务依赖
  composables ←  只依赖 utils/api，零视图依赖
  assets/styles ← 通过 CSS 变量统一调风格
关键约束：组件层不依赖业务逻辑，行为层不依赖视图。这样后续替换 SSE 协议、换 UI 框架、或单独测试某个 composable 都不会扩散到其他层。

8视觉刷新要点

本次重构顺便做了一轮克制的视觉刷新，保留品牌主色 #667eea → #764ba2，调整方向是"更通透、更柔和、更一致"：

  • 颗粒动画降噪：透明度从 1.0 降到 0.6 / 0.25，运动幅度从 20px 减到 16px，背景不再抢内容焦点
  • 圆角统一：引入 --radius-sm/md/lg/xl/pill 五档 token，全站圆角不再各自为政
  • 多层柔和阴影：--shadow-sm/md/lg/brand 替换原来散落的硬阴影，深度感更细腻
  • 过渡曲线统一：所有动效收敛到 --ease-out: cubic-bezier(0.16, 1, 0.3, 1)，手感一致
  • 玻璃感保留：backdrop-filter: blur 维持，但表面色值统一引用 token
修改全局视觉的入口只有两个文件：tokens.css（数值）与 chat.css / gradients.css（具体类名）。

9验证与后续建议

9.1 验证

  • npm run lint ✅ 无错误
  • npm run serve ✅ 编译成功
  • 本地探针（puppeteer-core + Edge）实测 5 个路由全部正常渲染： /login、/register、/menu、/ai-chat、/image-recognition
  • 功能、路由、接口契约、SSE 流式、TTS、RAG 上传 / 检索范围全部保持原行为不变

9.2 后续建议（更长远方向，本次未做）

下一步可考虑：把会话消息状态收敛到一个 composable（例如 useChatStore，不必引入 Pinia），让 useChatSend 只关心协议、不关心状态同步。当前 useChatSend 仍耦合了三处状态（currentMessages / sessions[id].messages / tempSession），行为正确但还能更瘦。这属于行为层的二次重构，会改变响应式数据结构，超出本次"组件关系清晰"的目标范围，故未在本次执行。

9.3 若遇白屏排查路径

  1. 先硬刷新（Ctrl + Shift + R）—— HMR 偶尔不能正确热替换大改动
  2. 若仍白屏，按 F12 打开控制台查看 Console 红色错误与 Network 失败请求
  3. 确认后端是否启动（/ai/chat/sessions 等接口 500 / 401 不会导致白屏，前端有 try/catch 兜底）
  4. 提供控制台错误信息以便定位
